# Board request contracts

`shared/requests.mjs` defines Zod fields and request objects once. HTTP routes
consume `httpRequests`; MCP registrations compose `mcpRequests` body fields with
explicit path arguments. JSON discovery is generated by the existing MCP adapter,
not maintained as a second schema. The tool inventory and result/error contracts
remain unchanged. This is request validation, not authorization: permissions,
ownership, content existence, stale revisions, mutation transactions, notification
fan-out and idempotency still run on the server.

## Transport rules

1. HTTP preserves numeric coercion for existing body IDs and path/query values.
   MCP requires numbers and advertises integer schemas. `requestId` supplies the
   shared integer/positive constraints to both.
2. Body objects preserve HTTP strictness/unknown-key stripping at their original
   call sites. MCP keeps its existing top-level unknown-key stripping. Path keys
   are removed before posting a body; HTTP bodies are not MCP argument objects.
3. Defaults (empty message/review text, empty attachment/thread ID arrays,
   false review escalation, search limit 30/offset 0) and nullable thread
   assignees follow the HTTP contract. MCP now applies these defaults locally;
   the server still validates them again. Existing idempotency headers and
   retry behavior are unchanged.
4. `threadListFields` supplies shared query field constraints. HTTP's legacy list
   adapter retains truthy/optional filter handling, comma-separated IDs, query
   truncation to 200 characters and offset clamping to 0–100000, including its
   permissive legacy numeric conversion. Paged mode still uses `paged=1`, a
   1–100 limit (default 50), status, and returned timestamp|ID cursor tuples;
   after takes precedence over before as before. Legacy mode ignores paging
   fields. This change leaves the existing four MCP list arguments/array result
   intact; TW-21 handles exposing bounded pages separately.
5. Global search maps MCP `query` to HTTP `q`, trims it, caps it at 200
   characters, and keeps bounded limit/offset. MCP requires `query`; HTTP still
   defaults a missing `q` to empty. List queries and global search intentionally
   retain their different historical normalization.
6. Attachment IDs in MCP use UUID fields. Existing HTTP attachment GET/DELETE
   handlers still look up raw path IDs and return 404 for unknown values; this
   change does not turn those responses into validation errors. Multipart
   upload and local filesystem paths are adapters, not JSON request bodies.
7. Git branch refinements are shared executable Zod checks. Basic pattern and
   length are advertised in JSON Schema; restrictions such as `..`, `.lock`,
   and empty path components are also checked by MCP before HTTP. JSON Schema
   cannot express every Zod refinement produced by the current converter.

## Local and mixed adapters

1. `prepare_branch_workspace` accepts a branch ID, reads branch/repositories/
   bootstrap over HTTP, then provisions a local Git checkout. Its filesystem/Git
   options are not an HTTP body.
2. `upload_attachment` accepts a local workspace path, validates confinement and
   file size locally, then sends multipart form data to POST /attachments.
3. `download_attachment` and `view_image_attachment` accept a shared UUID and
   perform raw GET /attachments/:attachment_id. Download also validates a local
   destination file path and exclusively creates it; image viewing validates
   MIME type and returns image content blocks. Neither is a JSON body contract.
4. `desktop_launch`, `desktop_list_windows`, `desktop_input`, and
   `desktop_screenshot` are local-only tools. Their current schemas stay beside
   their handlers; no corresponding HTTP validators exist to deduplicate.

## Intentional advertised input changes

MCP now advertises/enforces the existing server's title trim/1–240 update bound,
50,000-character message bounds, post-reply UUID arrays of at most 10, valid
channel names/1,000-character descriptions, branch names up to 150 characters
with Git restrictions, at most 100 linked threads, full 40-character lowercase
commit SHAs (including optional base), at most 200 inbox IDs, and bounded
schedule expressions (1–100 characters). `create_thread.assignee_id` now permits
null, matching HTTP. Existing server-valid calls remain supported, defaults and
nullable fields are preserved; inputs previously accepted by MCP only to fail
HTTP now fail locally. Local MCP validation has no HTTP status (`status: null`),
while direct HTTP validation remains 400. The public error envelope is unchanged.

`tests/request-contracts.test.mjs` checks actual tools/list discovery and real
stdio calls against HTTP boundaries, successful maximum-size content, trimming,
null/default/coercion behavior, invalid branch refinements and SHAs, idempotent
retries and stale-write protection. Existing MCP/work-queue/API tests cover
permissions, atomic claims, attachment paths and notification behavior.
